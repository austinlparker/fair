# blog-v2026 Design

## Overview

Replace the current Next.js + WhiteWind blog (`~/code/pds-blog`) with a Go CLI that publishes markdown posts as `standard.site` lexicon records to an ATProto PDS, then renders them as plain HTML — no CSS, no JS, browser defaults only — for static deploy to `aparker.io`.

**Goals:**
- PDS canonical: rendered site mirrors what's on the PDS, never the local markdown
- Pure HTML output: semantic elements, no stylesheets, no scripts, no client-side rendering
- ATProto-native: standard.site lexicons (`site.standard.publication`, `site.standard.document`), OAuth (loopback + DPoP + PAR), records portable to other standard.site readers (Leaflet, pckt)
- Domain-portable records: relative image paths in PDS records, resolved at build via `publication.url`
- End-to-end testable locally against a sandbox PDS before any prod write

**Non-goals:**
- Drafts (markdown sits unpublished if not ready; standard.site has no draft state)
- Comments (federate via Bluesky reply if ever needed)
- Analytics (no JS; server-side log analysis only)
- Syntax highlighting (`<pre><code>` + browser monospace; the no-CSS constraint stands)

## Architecture

### The three pieces

```
~/code/blog-posts/                 (existing authoring repo, untouched in shape)
  └─ wide-events/
     ├─ index.md                   (gray-matter frontmatter; CLI writes id back here)
     └─ images/foo.png

           │ fair publish path/to/index.md
           ▼

PDS (existing DID/handle, lexicon swap only)
  site.standard.publication/self   (one record per blog)
  site.standard.document/<rkey>    (one per post; rkey derived from path)
  blobs/                           (cover images only)

           │ fair build
           ▼

dist/                              (gitignored, atomic-swapped)
  ├─ index.html                    (post listing)
  ├─ wide-events/index.html        (path-based routing per document)
  ├─ images/<slug>/foo.png         (inline-image mirror)
  ├─ feed.xml                      (Atom 1.0)
  ├─ sitemap.xml
  ├─ 404.html
  └─ .well-known/
     ├─ site.standard.publication  (domain ownership)
     └─ oauth-client-metadata.json (OAuth client_id is this URL)

           │ wrangler pages deploy dist/
           ▼

aparker.io
```

### Identity rule

Once a markdown file is published, the PDS record is canonical. Markdown files are working copies. Re-running `fair publish` produces the same record (stable rkey derived from frontmatter `id` ULID). Deleting a markdown file does not delete the PDS record — use `fair unpublish` or `fair ls` to spot drift.

### Stack & libraries

- **Language:** Go (single static binary, `cmd/blog/main.go`)
- **CLI:** `spf13/cobra` for subcommand structure
- **Markdown:** `github.com/yuin/goldmark` (CommonMark + GFM extensions); pinned version, golden-file CI test for round-trip stability
- **Frontmatter:** `github.com/adrg/frontmatter` (YAML)
- **ATProto:** `github.com/bluesky-social/indigo/atproto` (XRPC client) + `github.com/haileyok/atproto-oauth-golang` (OAuth + DPoP + PAR + nonce rotation)
- **Token storage:** `github.com/99designs/keyring` (OS keychain) with `~/.config/fair/session.<profile>.json` 0600 fallback
- **ULID:** `github.com/oklog/ulid/v2`
- **Grapheme-correct truncation:** `github.com/rivo/uniseg`
- **TOML config:** `github.com/BurntSushi/toml`

### Auth

ATProto OAuth loopback flow. CLI binds an ephemeral port at `http://127.0.0.1/callback`, opens browser to PDS authorization endpoint, intercepts redirect, exchanges code for tokens. DPoP and PAR are mandatory and handled by `haileyok/atproto-oauth-golang`. Client metadata hosted at `https://aparker.io/.well-known/oauth-client-metadata.json` (deployed as part of `dist/`); `client_id` is that URL. Bootstrap requires deploying an empty/cold-start `dist/` once before first auth — handled by the cold-start contract on `fair build`.

### Profile mechanism

`--profile <name>` flag (also `FAIR_PROFILE` env). No default — required always. Allowlist of known profiles (typo rejection with Levenshtein-≤2 suggestion). Each profile has separate config file, state file, images-mirror dir, dist dir, and keychain entry (service name `blog-<profile>`, key `oauth-tokens-<profile>`).

```toml
# ~/.config/fair/config.prod.toml
pds_url           = "https://bsky.social"   # or your PDS endpoint
did               = "did:plc:..."
domain            = "https://aparker.io"
publication_name  = "Austin Parker"
blog_posts        = "/Users/austinparker/code/blog-posts"
state_file        = ".fair/state.prod.json"
images_mirror     = "images-mirror.prod/"
dist_dir          = "dist/"
cloudflare_project = "aparker-blog"

# ~/.config/fair/config.sandbox.toml
pds_url           = "http://localhost:2583"
domain            = "http://localhost:8000"
# (no cloudflare_* — deploy command errors on sandbox)
```

### Data shape

**Publication record** — singleton at `at://<did>/site.standard.publication/self`:

```json
{
  "$type": "site.standard.publication",
  "url": "https://aparker.io",
  "name": "Austin Parker",
  "description": "(optional)",
  "icon": "(optional blob)"
}
```

**Document record** — one per post at `at://<did>/site.standard.document/<rkey>`:

```json
{
  "$type": "site.standard.document",
  "site": "at://<did>/site.standard.publication/self",
  "title": "Wide Events and Personal Software",
  "publishedAt": "2025-08-14T00:00:00.000Z",
  "path": "/wide-events-and-personal-software",
  "description": "(frontmatter or first-paragraph extraction, ≤3000 graphemes)",
  "coverImage": "(optional typed blob, ≤1MB)",
  "tags": ["observability"],
  "content": {
    "$type": "site.standard.content.markdown",
    "text": "...full markdown body, inline image URLs are RELATIVE (/images/<slug>/foo.png)...",
    "version": "1.0"
  },
  "textContent": "(plaintext, ≤30000 graphemes, code fences stripped)",
  "updatedAt": "(set on republish if content hash changed)"
}
```

**Frontmatter mapping:**

| Frontmatter | Record field | Notes |
|---|---|---|
| `id` (ULID) | (used for rkey derivation, not a record field) | Written back by CLI on first publish |
| `title` | `title` | Required |
| `date` | `publishedAt` | Required, normalized to RFC3339 |
| `description` | `description` | Optional; fallback = first AST paragraph in first 5 nodes; truncated grapheme-aware to ≤3000 |
| `cover` | `coverImage` (blob) | Optional; relative path; uploaded via `com.atproto.repo.uploadBlob`; ≤1MB enforced client-side |
| `tags` | `tags` | Optional YAML list; sorted/lowercased/deduped before record write |
| `slug` | `path` and rkey | Optional override; default = directory name; grammar `[a-z0-9-]+`; reserved names rejected (self/index/feed/sitemap/.well-known) |
| `updated` | `updatedAt` | Optional; auto-set if content hash changed |

**Inline images:** stored as RELATIVE paths (`/images/<slug>/foo.png`) in `content.text`. Build resolves against `publication.url` to emit absolute URLs in the static HTML. Records are domain-portable.

### Identity & rename detection

Each post has a stable ULID `id` written back to its frontmatter on first publish (the CLI's only mutation of `blog-posts/`). Identity follows the `id`, not the path. Rename detection is local-first via `state.json` (O(1) lookup); falls back to paginated PDS scan only if `id` not in local state. `fair rename old new` deletes the old record and republishes under the new rkey atomically.

### Hash determinism (idempotency)

`fair publish` skips re-putting a record when the content hash hasn't changed. Hash inputs:

- Markdown body re-serialized via pinned goldmark (LF line endings, BOM stripped)
- Frontmatter canonicalized (sorted keys, no comments, no trailing whitespace, sans `id`/`updated`/`updatedAt`)
- Cover image **source file** SHA-256 (not blob CID — known pre-upload, no wasted upload on no-op)
- Tags: sorted, lowercased, deduped

Cached at `.blog/state.<profile>.json` per rkey: `{id, lastHash, lastCoverHash, lastPublishedAt}`. State file written via temp+rename for atomicity. `--force` flag bypasses hash check.

Golden-file CI test asserts byte-stable goldmark round-trip on the 11 existing posts.

### Atomic build

Build writes to `dist.tmp/`. On success: `mv dist/ dist.old.<pid>/; mv dist.tmp/ dist/; rm -rf dist.old.<pid>/` (skip first mv if no `dist/` yet). Build start sweeps any leftover `dist.old.*` from a prior crash. Any `listRecords` pagination error during build aborts hard with no swap — partial site never deployed.

### Cold-start contract

`fair build` MUST succeed with no auth, no publication record, and zero documents. On cold start it emits:

- `.well-known/oauth-client-metadata.json` (always)
- `.well-known/site.standard.publication` (stub or echo of publication record if present)
- Empty but well-formed `feed.xml`, `sitemap.xml`
- Stub `index.html`, `404.html`

This unblocks the bootstrap chicken-and-egg: deploy empty `dist/` → OAuth metadata reachable → `auth login` works → `init publication` works → first publish.

### Local sandbox

`bluesky-social/pds` Docker image at `localhost:2583`. Account creation via `goat` CLI (host prerequisite, not in container). Custom lexicons rely on PDS optimistic validation default. CLI's `fair sandbox up/down/reset/serve` orchestrate compose lifecycle and embed an in-process HTTP server for client metadata + dist preview (replaces the Python `http.server` first considered). Profile-isolated state — sandbox cannot touch prod records, prod cannot touch sandbox records.

Integration tests use `--project-name=blogtest_<random>` + ephemeral host port for parallelism, gated behind `//go:build sandbox`.

## Existing Patterns

### From `~/code/pds-blog` (current Next.js + WhiteWind)
- **Reuse the markdown→PDS shape** of `blog-posts/migrate/index.ts` — frontmatter parsing, image URL rewriting, `putRecord` flow. Lexicon swap from `com.whtwnd.blog.entry` to `site.standard.document`.
- **Reuse markdown plugin intent** (GFM, sanitize) from `post/[rkey]/page.tsx:192-200`, but reimplemented in goldmark.
- **Reuse Cloudflare Pages deploy** (`wrangler pages deploy`) — same project, same domain, swap the asset source from Next.js output to `dist/`.
- **Discard:** Tailwind, theme toggle, BlueskyPostEmbed iframe component, react-markdown, bright syntax highlighter, lucide icons, `next-themes`, all `"use client"` boundaries. None survive the no-CSS/no-JS constraint.

### New patterns introduced
- **Profile-isolated CLI state** (config + state.json + keychain entry per profile). New for this project; no precedent in `pds-blog`.
- **Hash-driven idempotent publish** with local state cache. New.
- **Cold-start build contract** (works with zero PDS reachable). New.

### Identifiers
- **DID/handle:** unchanged from existing PDS account
- **Domain:** `aparker.io` (per user memory; *not* austinparker.me)
- **Cloudflare Pages project:** existing project, source swap

## Additional Considerations

**Implementation scoping:** 7 phases, within the 8-phase limit for writing-plans.

**Build trigger** is intentionally left manual + optional GitHub Action for now. Jetstream listener was explicitly ruled out — a daemon contradicts the static-redeploy model.

**Domain portability:** Records contain only relative image paths and an AT-URI for `site` (not a URL). Switching domains requires updating the publication record's `url` field and redeploying. No bulk record rewrite needed. OAuth client metadata moves with the domain (it's at `<domain>/.well-known/oauth-client-metadata.json`); a re-login is required after the switch.

**Inline-image domain coupling tradeoff:** External standard.site readers (Leaflet, pckt) render inline images by joining the relative URL with `publication.url`. If aparker.io is unreachable, those images don't render in external readers. Acceptable for a personal blog under the user's own domain; documented here so future work doesn't accidentally migrate to PDS-blob inline images without revisiting the spec extension.

**Failure-mode tolerances:**
- Orphaned blob (uploadBlob ok, putRecord fail): tolerated; `doctor` flags; PDS GC reclaims eventually.
- state.json corruption: surfaced via clear error message ("published OK but local state corrupted; run `fair doctor`").
- Source markdown file dirty after partial publish: re-running publish is idempotent (id stable, hash recomputed).
- listRecords mid-pagination failure: hard abort, no atomic swap.

**textContent truncation** is loud (warn to stdout with from/to counts), grapheme-aware (uniseg), never silent.

**Cross-platform:** macOS and Linux only. `runtime.GOOS == "windows"` causes early-exit in `fair sandbox *` with a clear "use WSL2" message. CLI itself is GOOS-portable in principle but only macOS+Linux are tested.

**Repository conventions:** This is the user's project; `~/code/hound` documented `jj` workflow patterns are NOT applicable here (different project, blog-v2026 uses straight `git`/`jj` colocate per user preference). Confirm during Phase 1 if `jj` colocate is desired (default: yes, matches user's pattern).
